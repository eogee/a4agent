# a4agent v0.6.1

## 新增：OpenCode 接入 —— 与其他六端完全同权

如果你在用 OpenCode，v0.6.1 之后它就是 a4agent 里的第七个端：本机装了就能用——服务密码与默认端口 `49374` 自动发现，**没有任何专属卡片、开关或地址密码表单**，出现的唯一位置和其他端一模一样。

**任务下发新增 OpenCode 引擎**

引擎列表里会自动出现 OpenCode（服务在跑就亮）。选中它下发任务时，走的是「对运行中的服务建会话」，而不是每次新起一个 CLI 进程：

| | 其它六端 | OpenCode |
|---|---|---|
| 免审批 | 全局开关（`--yolo` / `bypassPermissions`） | **会话级权限规则**，不碰你的全局配置，任务结束即失效 |
| 成败判定 | 从退出码反推 | 服务端直接给 `outcome`（成功/失败/被中断）+ 成本 + 用量 |
| 取消 | 杀整棵进程树 | 对服务端会话发 interrupt |

**「会话交互」表格新增 OpenCode 一行**

「通知提醒」页的宿主表格多了 OpenCode，点「注册」即开启服务事件监听：

- 你在 OpenCode 网页端里发起的会话，跑完、出错或被中断，都走同一条桌面横幅 + 手机推送
- 外出·手机优先模式下，**权限请求推手机批办**：批准 / 总是允许 / 拒绝三个按钮，批复经 OpenCode 的 permission API 回给服务，会话随即继续
- OpenCode 没有 hook 协议，注册**不写它的任何文件**；在 OpenCode 界面里亲自批过的请求，手机上迟到的按动作按已失效处理

**技能与 MCP 同步覆盖第七端**，并按 OpenCode 的真实行为做了适配：

- **技能**：全局在 `~/.config/opencode/skills`（不是 `~/.opencode/skills`），项目级 `.opencode/skills`
- **MCP**：配置在 `opencode.json(c)` 的 `mcp.servers`，只支持 stdio 与 Streamable HTTP

## 改进：不再为「已经能用」的技能白迁一份

OpenCode 会自动发现 `~/.claude/skills` 与 `~/.agents/skills`。落在这些目录里的技能，界面现在会标注**「OpenCode 已可见，无需重复迁移」**，「一键适配全部端」也会跳过它们。

## 修复：4 处实测暴露的问题

- **项目级 OpenCode 配置写入位置修正**：`.opencode/` 内的配置会**覆盖**项目根目录的同名文件，此前按相反顺序探测，会把 MCP 写进一个 OpenCode 永远不读的文件里
- **跨端迁移不再误删可用技能**：OpenCode 的技能身份是目录名，此前仅显示名相同、ID 不同的既有技能会被当成冲突移进回收站
- **模型被上游废弃时会自动换一个重试**：实测存在「清单里标着可用、真跑却报已废弃」的模型，现在下发与预检会自动换候选模型重试
- **OpenCode 事件不再丢批**：事件流早期按每秒 1 条节流（终局提醒够用），权限批办走同一条流后，审批请求撞上事件风暴会被静默丢弃，已取消节流

## 兼容性说明

- Windows 10/11 64 位
- **OpenCode 引擎与会话监听默认关闭**：没装 OpenCode 时引擎置灰、表格行为未注册，不影响任何既有行为；技能与 MCP 的第七端支持默认生效
- 旧版勾过「启用接入」的配置会在升级后自动迁移为表格里的注册状态
- 配置与数据仍存于 `%APPDATA%\a4agent`，升级全程保留

## 升级说明

直接运行 `a4agent-setup-0.6.1.exe` 覆盖安装即可。
