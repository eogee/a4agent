# a4agent v0.6.1

## 新增：OpenCode 接入 —— 直接接管你已经开着的那台 OpenCode

如果你在用 OpenCode，v0.6.1 之后不必再把它当成一个「外部工具」对齐配置：a4agent 接管的就是**你已经开着的那台服务**。本机装了就能用——它会自动读取 OpenCode 的服务密码与默认端口 `49374`，不需要你填任何东西。到「通知提醒」页勾选启用即可。

**任务下发新增 OpenCode 引擎**

选中它下发任务时，走的是「对运行中的服务建会话」，而不是每次新起一个 CLI 进程。三个差别是刻意换来的：

| | 其它六端 | OpenCode |
|---|---|---|
| 免审批 | 全局开关（`--yolo` / `bypassPermissions`） | **会话级权限规则**，不碰你的全局配置，任务结束即失效 |
| 成败判定 | 从退出码反推 | 服务端直接给 `outcome`（成功/失败/被中断）+ 成本 + 用量 |
| 取消 | 杀整棵进程树 | 对服务端会话发 interrupt |

**通知提醒覆盖 OpenCode 网页端的会话**

你在 OpenCode 网页端里发起的活，跑完、出错或被中断，都会走同一条桌面横幅 + 手机推送——不必专门回 OpenCode 看一眼。

**远程服务**：在同一张卡片里填地址与密码即可（密码用 Windows DPAPI 加密存储，界面永不回显）。

## 新增：OpenCode 成为第七个被托管的端

技能与 MCP 管理现已覆盖 OpenCode，并按它的真实行为做了适配：

- **技能**：全局在 `~/.config/opencode/skills`（不是 `~/.opencode/skills`），项目级 `.opencode/skills`
- **MCP**：配置在 `opencode.json(c)` 的 `mcp.servers`，只支持 stdio 与 Streamable HTTP；写文件前自动备份，读取失败时中止写入而不是按空配置重建

## 改进：不再为「已经能用」的技能白迁一份

OpenCode 会自动发现 `~/.claude/skills` 与 `~/.agents/skills`。落在这些目录里的技能，界面现在会标注**「OpenCode 已可见，无需重复迁移」**，「一键适配全部端」也会跳过它们——以前会白白多拷一份。

## 修复：4 处会让人白等或丢配置的问题

- **项目级 OpenCode 配置写入位置修正**：`.opencode/` 内的配置会**覆盖**项目根目录的同名文件，此前按相反顺序探测，会把 MCP 写进一个 OpenCode 永远不读的文件里——写完看似成功、实际不生效
- **跨端迁移不再误删可用技能**：OpenCode 的技能身份是目录名。原先仅显示名相同、ID 不同的既有技能会被当成冲突移进回收站，现在按各自端的口径判定
- **模型被上游废弃时会自动换一个重试**：实测存在「清单里标着可用、真跑却报已废弃」的模型；现在下发与预检遇到这种失败会自动换候选模型重试，而不是直接判任务失败
- **接口首开不再报错**：新增的连接配置卡片在未启用状态下会返回正常响应

## 兼容性说明

- Windows 10/11 64 位
- **OpenCode 接入默认关闭**，不勾选不影响任何既有行为；技能与 MCP 的第七端支持则是默认生效的
- OpenCode 端不要求你有生效的配置方案（它的模型与凭据在 OpenCode 里）
- 配置与数据仍存于 `%APPDATA%\a4agent`，升级全程保留
- OpenCode 的配置文件是 JSONC：a4agent 能正确读取带注释的既有文件，但写入时会**丢失该文件里的手写注释**（整子树替换的固有取舍）；介意请在 OpenCode 自己的界面里改

## 升级说明

- 直接运行新版 `a4agent-setup-0.6.1.exe` 覆盖安装即可，数据与配置（`%APPDATA%\a4agent\`）全程保留
